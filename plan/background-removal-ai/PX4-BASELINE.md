# PX4 baseline — the parity oracle against today's preview

> Task PX4.3 of [`07-TASKS-AND-EVIDENCE.md`](./07-TASKS-AND-EVIDENCE.md); oracle spec in
> [`09-PREVIEW-EXPORT-PARITY.md`](./09-PREVIEW-EXPORT-PARITY.md) ("PX4 — the pixel parity oracle").

**Source:** CI only. Workflow `CI`, job `preview-parity-oracle`, run
[35172331641](https://github.com/rojan-labs/FramePilot/actions/runs/35172331641) at `c94291f2`
(Google Chrome, ubuntu-latest, SwiftShader CPU GL), artifact `preview-parity-results`. This file and
`tests/e2e/fixtures/preview-parity-baseline.json` were generated from that artifact with
`node tests/e2e/scripts/px4-baseline.mjs [--write-baseline]`. Nothing here was run locally: a local
full run exhausted a workstation's memory, and the harness documents that it is CI-only. The
first baseline (run 35140382484 at `700f4e7d`, today's preview before PX2) listed 42 failing
cases; the layer compositor (PX2) brought it to the 5 below.

**Gates (unchanged from 09, tightened only):** PSNR ≥ 40 dB whole frame; max per-channel error ≤
8/255 on ≥ 99.5% of pixels; sentinel layer colours exact (same visible set, no pixel that is solidly
one layer in both frames showing a different layer); presented source pts per picture layer ==
frame plan, back to front. A timeline the desktop monitor routes to the DOM `PreviewPlayer` is a
`renderer: DOM` failure and is not read back (its other checks fail with that reason).

**How CI stays honest:** every failing check below is a `test.fail()` in
`preview-parity-oracle.spec.ts`, keyed off the baseline JSON. A listed check that starts passing
fails the job ("expected to fail, but passed"), so the list can only shrink as PX2 lands; a check
that newly fails is not listed and fails the job.

## Summary

- **48 cases. 43 pass every check; 5 fail** (pixels 5, sentinel 2; renderer and pts pass everywhere).
  Every case now renders on the layer compositor (`renderer: WebCodecs`); no case is routed to the
  DOM player.
- **Blocked on MK3 — `alpha/mask-shapes`:** t=1 (a static rectangle) passes; t=3 (a keyframed
  ellipse over a subtracted path, a two-mask stack) is 10.21 dB with 278,161 px showing a different
  layer. The compositor draws today's single-shape masks (`clip-mask.ts`); a multi-mask v22 stack
  needs the exact rasteriser (`render/mask_stack.py` + `mask_raster.py`), which is MK3.
- **Not synthesisable by the oracle — `alpha/matte-text-behind-subject`** (BR2's vector): the
  engine refuses every sample ("Background removal data is missing — run Remove background again",
  `matte_missing`) because the generator has no matte artifact to write. Pixels and sentinel are
  listed with that reason; renderer and pts pass.
- **Text glyph rasterisation — `text/text-only` 38.74 dB, `text/text-transform` 37.02–39.58 dB,
  `text/caption-track-order` 39.79 dB** (99.53–99.87% of pixels within 8/255, above the 99.5%
  gate; only PSNR fails). Layout is exact (Pillow's integer pens, bboxes, wrap and ascent from
  shipped metrics; `text/text-above`, `text-below`, `text-between` pass). The remaining error is
  inside glyph edges: Pillow rasterises with FreeType's TrueType hinting (stems and bars snapped
  to the pixel grid, linear coverage), the browser draws unhinted outlines with its own coverage.
  Decision needed (see the PX2 report): ship Pillow-rendered glyph coverage for the default sizes,
  or a FreeType build, or accept.
- **PX0.3 colour:** canvas2d (the compositor's own shader path) max error 0 for all four encodings.
  The harness's separate Chromium `VideoFrame`→WebGL texture measurement stays at 9/255 for BT.709
  limited range (listed as `colour.bt709-limited: [webgl]`); the compositor does not use that path.

# PX4 baseline — the parity oracle against today's preview

> Task PX4.3 of [`07-TASKS-AND-EVIDENCE.md`](./07-TASKS-AND-EVIDENCE.md); oracle spec in
> [`09-PREVIEW-EXPORT-PARITY.md`](./09-PREVIEW-EXPORT-PARITY.md) ("PX4 — the pixel parity oracle").

**Source:** CI only. Workflow `CI`, job `preview-parity-oracle`, run
[35140382484](https://github.com/rojan-labs/FramePilot/actions/runs/35140382484) at `700f4e7d`
(Google Chrome, ubuntu-latest, SwiftShader CPU GL), artifact `preview-parity-results`. This file and
`tests/e2e/fixtures/preview-parity-baseline.json` were generated from that artifact with
`node tests/e2e/scripts/px4-baseline.mjs [--write-baseline]`. Nothing here was run locally: a local
full run exhausted a workstation's memory, and the harness now documents that it is CI-only.

**Gates (unchanged from 09, tightened only):** PSNR ≥ 40 dB whole frame; max per-channel error ≤
8/255 on ≥ 99.5% of pixels; sentinel layer colours exact (same visible set, no pixel that is solidly
one layer in both frames showing a different layer); presented source pts per picture layer ==
frame plan, back to front. A timeline the desktop monitor routes to the DOM `PreviewPlayer` is a
`renderer: DOM` failure and is not read back (its other checks fail with that reason).

**How CI stays honest:** every failing check below is a `test.fail()` in
`preview-parity-oracle.spec.ts`, keyed off the baseline JSON. A listed check that starts passing
fails the job ("expected to fail, but passed"), so the list can only shrink as PX2 lands; a check
that newly fails is not listed and fails the job.

## Summary

- **43 cases, 184 samples. 1 passes every check** (`geometry/crop`: 45.50 dB, 100% within 8/255).
- **25 cases: `renderer: DOM`** (every stacked/masked/blended/keyframed stack, every text or caption
  timeline, every retimed clip, the unproxied original). Matches the PX0.2 derivation case for case.
- **17 WebCodecs cases fail:** pixels 17, pts 9, sentinel 7.
  - **Single-picture resampling floor:** `layering/layers-1`, `hidden-track`, `trims-non-keyframe`
    sit at 37.27–37.28 dB with 99.85–99.87% of pixels within 8/255: the browser's `drawImage`
    downscale (1920x1080 → 1280x720) differs from the engine's ffmpeg scale at edges (the frame
    counter blocks). Below the 40 dB gate on the simplest possible timeline.
  - **Flat EDL (pts):** `layers-2/3/5` present one layer where the plan has 2/3/5
    (e.g. `presented [land@15] != plan [square@75, port@45, land@15]`); pixels still fail at the
    resampling floor because the front layer hides the rest.
  - **Clip end:** `layers-1` at t=4.0 presents `land@179` where the export has no picture (end-exclusive).
  - **Speed ramp:** `time/speed-ramp` presents `land@67` for plan `land@68` (off by one; the canvas
    does not integrate the ramp), min 28.37 dB.
  - **Transitions:** all four WebCodecs transition cases fail pixels, sentinel and pts. The under-layer
    is a held frame of the previous shot (`presented [land@300, four3@367] != plan [land@367, four3@367]`;
    edges: `land@1740` for `land@1799`), and whole-frame sentinel disagreements (166k–338k px) show
    the wrong layer during the ramp. Min PSNR 8.02–13.73 dB.
  - **Colour/effects:** `colour/grade` 20.32 dB and the grade's `land/primary` sentinel missing;
    `colour/lut` 20.91 dB (LUT not applied); `effects/effect-kinds` min 2.12 dB with sentinel
    disagreements.
  - **Geometry:** `fit-portrait-in-landscape` 34.95 dB, `fit-mixed-aspects` 34.77 dB (26% within
    8/255); `fit-landscape-in-portrait` fails on size: the canvas is 720x1280 for a 1080x1920 project,
    so no pixel comparison is possible (the oracle compares at the same resolution and does not
    rescale either side).
- **PX0.3 colour:** BT.709 limited range fails on both the canvas2d and WebGL paths (max 9/255);
  BT.601 limited/full and BT.709 full pass (≤ 2/255). Details in
  [`PX0-INVENTORY.md`](./PX0-INVENTORY.md#px03--chromium-colour-conversion).
